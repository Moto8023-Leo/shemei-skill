# shemei_skill 前端与飞书表格 — 缺失与优化分析

> 基于 shemei_skill（生产环境）vs v2.1/v2.2/v2.3 升级版本对比
> 分析日期：2026-07-24

---

## 综述

shemei_skill 和 v2.x 系列是 **两套独立技术栈** 的同一业务系统：

| 维度 | shemei_skill（生产） | v2.3（最新升级版） |
|------|---------------------|---------------------|
| 后端 | Python / FastAPI | Node.js / Express / TypeScript |
| AI 引擎 | DeepSeek API | Claude API + GPT Image |
| 前端 | React 19 + TDesign + Zustand + Hash Router | React + Vite + Pure CSS（单页模态） |
| 飞书集成 | Python 原生驱动（2品牌×3表） | TypeScript 服务层（多品牌共用表） |
| 页面数 | 10 个独立路由页面 | 1 个单页 + 模态面板 |

v2.3 在 **安全机制、内容质量、发布流程、权限管理** 等方面比 shemei_skill 成熟得多。以下逐项分析。

---

## 一、前端缺失功能（严重程度排序）

### 🔴 严重缺失（影响安全/合规）

#### 1. 内容版本历史与对比
- **v2.3 有**：每次生成/重排版/审核/发布/恢复均创建版本快照；版本间 Diff 对比；历史版本恢复（清除旧审核+发布结果）
- **shemei_skill 现状**：❌ 完全没有。每次生成覆盖前次结果，无任何历史记录
- **风险**：误操作后无法恢复；发布后发现问题无法追溯是哪个版本
- **建议**：在飞书排期表增加「版本历史」字段（JSON 文本），或本地建 versions.json

#### 2. 逐平台发布前审核
- **v2.3 有**：3 项全局确认（产品完整性/无遮挡/事实准确）+ 3 项逐平台确认（文案已审核/图片已审核/账号已审核），全部勾选才能发布
- **shemei_skill 现状**：⚠️ 有 `审核状态` 字段（草稿→已生成→已确认→已发布），但 UI 中无结构化审核清单，仅依赖人工自觉
- **风险**：可能发布未经审核的内容到生产环境
- **建议**：在 Workbench 的 RightRail 增加审核清单组件

#### 3. 参数安全表达（Range Safe Expression）
- **v2.3 有**：`facts.service.ts` 自动检测区间值（如"40-65km"），修正为本地化限定表达（"UP TO 65KM RANGE" 等 6 种语言）；未带限定词的续航值阻塞发布
- **shemei_skill 现状**：❌ 没有此机制。产品规格中的区间值直接传给 AI，可能生成违规广告文案
- **风险**：欧盟/英国广告合规风险（续航必须标注为"最高可达"）
- **建议**：在 `content_factory.py` 提示词中增加参数安全规则，或在服务端做后处理校验

#### 4. 防重复生成
- **v2.3 有**：前端按钮锁定 + 后端 SHA-256 请求指纹去重（10 分钟内相同参数复用任务）
- **shemei_skill 现状**：⚠️ 有 `generating` 状态锁但无后端去重；用户快速连点可能触发多次 DeepSeek API 调用
- **建议**：在 `/api/generate` 端点增加请求指纹缓存（5 分钟内去重）

---

### 🟡 中度缺失（影响效率/体验）

#### 5. 内容去重检测
- **v2.3 有**：五维度相似度检测（Hook/卖点/CTA/场景/构图），0-100 风险评分，中文建议文案
- **shemei_skill 现状**：❌ 无
- **建议**：在 `quality_engine.py` 中增加与历史内容的相似度对比

#### 6. 1.5 秒自动保存草稿
- **v2.3 有**：localStorage + 后端 `drafts.json` 双重持久化，失败 ~30 秒后自动重试
- **shemei_skill 现状**：⚠️ `useStudioStore` 有 `saveDraft`/`loadDraft` 但仅存 localStorage，无后端持久化
- **建议**：增加后端 `/api/drafts` 端点，前端增加防抖自动保存

#### 7. 图片文字覆盖拖拽编辑器
- **v2.3 有**：可拖拽调整文字块位置（X/Y/宽度/字号/遮罩/对齐），后端安全钳制边界，一键应用到三种尺寸
- **shemei_skill 现状**：⚠️ 有叠加模板（促销/极简/卖点）+ 位置选择（左/右/底部），但无自由拖拽。文字排版由 `canvasOverlay.ts` 固定算法生成
- **建议**：在 WorkspacePanel 中增加拖拽交互，将坐标存入 state 传给 canvasOverlay

#### 8. 确定性随机（Creative Seed）
- **v2.3 有**：`creativeSeed` + SHA-256 种子驱动随机风格，可复现；锁定/重随机按钮；生成结果展示完整风格摘要
- **shemei_skill 现状**：⚠️ `visual_engine.py` 做随机风格选择但无种子机制，不可复现
- **建议**：引入 seed 参数并暴露给前端

#### 9. 四层质量评分体系
- **v2.3 有**：blocking（阻止发布）/ warning（优化提醒）/ manual（人工检查）/ passed（已通过）
- **shemei_skill 现状**：⚠️ `quality_engine.py` 有 AI 评分（0-100）+ 各维度指标，但无分层门槛机制
- **建议**：将评分重构为四层体系，blocking 项直接锁发布按钮

#### 10. 基础图片复用建议
- **v2.3 有**：`cache.service.ts` 搜索历史中的匹配底图，仅重新应用文字覆盖和平台尺寸
- **shemei_skill 现状**：❌ 每次重新生成完整图片
- **建议**：低优先级——DeepSeek 不涉及图片生成 API 费用，复用价值主要体现在速度

---

### 🟢 轻度缺失（锦上添花）

#### 11. 权限系统
- **v2.3 有**：四角色（admin/content ops/reviewer/viewer），后端双重校验，品牌级数据隔离
- **shemei_skill 现状**：❌ 无任何权限控制
- **说明**：当前为单人使用场景，暂不需要

#### 12. 费用追踪
- **v2.3 有**：按 provider/brand/country 记录成本 + 月度预估
- **shemei_skill 现状**：❌ 无
- **说明**：DeepSeek 费用极低，暂不需要

#### 13. Prompt 中心（版本化管理）
- **v2.3 有**：5 类提示词分类管理，版本历史，激活切换
- **shemei_skill 现状**：⚠️ 有 `data/prompts/` 静态模板文件，但无 UI 管理界面
- **建议**：在 Settings 页增加提示词编辑功能

#### 14. 月度营销计划生成
- **v2.3 有**：按产品/国家/月份自动生成周主题+产品卖点+视觉风格
- **shemei_skill 现状**：❌ 无

#### 15. 发布队列系统
- **v2.3 有**：定时发布/失败重试含退避/成功平台跳过/服务重启自动恢复
- **shemei_skill 现状**：⚠️ 有 `daemon.py` 定时任务 + `content_queue.json`，但缺少细粒度重试和恢复机制

#### 16. 同步日志
- **v2.3 有**：双向飞书同步追踪（success/failure/skipped），失败自动重试
- **shemei_skill 现状**：❌ 无。飞书写入失败仅 log 到控制台

#### 17. 三层营销日历
- **v2.3 有**：公共节假日 + 商业营销节点 + 品牌自定义活动
- **shemei_skill 现状**：⚠️ 有前两层（`calendar_engine.py`），缺品牌自定义活动

#### 18. 侧边栏折叠 + 响应式布局
- **v2.2 引入**：四段手风琴参数面板 + 可折叠侧边栏 + 三档响应式断点
- **shemei_skill 现状**：桌面固定三栏布局，无折叠和响应式

## 三、前端架构优化建议

### 3.1 状态管理

shemei_skill 使用 4 个 Zustand Store，v2.3 使用 App.tsx 中的 useState 单体。shemei_skill 在这方面设计更好，建议维持。

### 3.2 API 客户端

- **shemei_skill**：各处直接 `fetch()` 调用，无统一错误处理/重试
- **v2.3**：`api.ts` 封装了 35+ 方法，带 `x-studio-user` 头、自动重试、AbortController 超时

📌 **建议**：shemei_skill 前端应创建统一的 API 客户端模块，至少包含：
- 请求/响应类型定义
- 超时处理（当前仅 health check 有 5s 超时）
- 统一错误提示

### 3.3 类型系统

- **shemei_skill**：类型内联在 store/组件中，无独立 types 文件
- **v2.3**：`types.ts` 集中管理所有类型定义

📌 **建议**：创建 `web/src/types.ts` 集中管理类型

### 3.4 生成任务进度

- **v2.3**：`JobProgress.tsx` 实时显示阶段（文案→图片→合成）+ 百分比 + 日志
- **shemei_skill**：仅显示 loading spinner + "正在生成" 文本

📌 **建议**：在 WorkspacePanel 中增加阶段性进度展示

## 四、优化优先级矩阵

```
                    影响大
                      │
         ┌────────────┼────────────┐
         │  优先做     │  立即做    │
         │  ·种子随机  │  ·参数安全 │
         │  ·拖拽编辑  │  ·逐平台审核│
         │  ·Prompt   │  ·版本历史  │
   简单──┼────────────┼────────────┼──复杂
         │  可延后    │  按需做    │
         │  ·费用追踪 │  ·权限系统  │
         │  ·响应式   │  ·发布队列  │
         │  ·月度计划 │  ·内容去重  │
         └────────────┼────────────┘
                      │
                    影响小
```

### 立即可做的（低成本高收益）

| # | 事项 | 改动范围 | 预计工时 |
|---|------|---------|---------|
| 1 | 参数安全表达（Range Safe） | `content_factory.py` 增加规则 | 30min |
| 2 | 请求去重（5min 缓存） | `server.py` /api/generate | 30min |
| 3 | 飞书表增加「折扣代码」独立字段 | 飞书手动改表 + `feishu_driver.py` | 15min |

| # | 事项 | 改动范围 | 预计工时 |
|---|------|---------|---------|
| 5 | 内容版本历史 | `feishu_driver.py` + 飞书表 + 前端 | 3h |

| 7 | 四层质量评分体系 | `quality_engine.py` + 前端 | 2h |
| 8 | Creative Seed 确定性随机 | `visual_engine.py` + ParameterPanel | 1h |

## 五、shemei_skill 的独特优势（保留）

以下方面 shemei_skill 做得比 v2.3 更好，应保留：

1. **多页面路由架构** — 10 个独立页面比单页面板更清晰，适合运营人员日常使用
2. **TDesign 组件库** — 专业 UI 比纯 CSS 维护成本低
3. **多品牌独立表** — 每个品牌 3 张表，数据隔离更干净
4. **Daemon 守护进程** — Python 定时任务比 v2.3 的进程内队列更稳健
5. **X/Twitter 双通道** — twikit API + Chrome 浏览器回退，比 v2.3 的纯人工确认更自动化
6. **Canvas 叠加引擎** — 客户端合成比服务端 SVG 合成更灵活
7. **Zustand 状态管理** — 比 v2.3 的 useState 单体更模块化
